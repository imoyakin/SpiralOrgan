# Architecture Principles

## 目标

给 SpiralOrgan 建立长期稳定的架构约束，避免后续功能增长导致失控耦合。

## 架构原则

1. 引擎与策略分离  
   引擎负责执行，策略负责“是否允许执行”。

2. 默认 pipeline + 用户可编辑 pipeline  
   提供官方默认模板，同时允许用户定义和替换节点/连线/条件。

3. 能力开关化  
   每个高能力模块都必须有 `enabled` 开关和风险级别。

4. 多角色必选，单角色可退化  
   默认角色编排为 4 角色，低配模式可退化。

5. 统一上下文总线  
   看板、记忆、审计、审批进入统一上下文访问层。

6. 客户端/内核解耦  
   Flutter 作为控制面，Rust 内核支持 remote/embedded 双模式。

7. 未来 ECS 管理面预留  
   当前 pipeline 为过渡实现，最终迁移到 WorldDefine ECS 驱动。

## 约束

- 不允许把审批逻辑硬编码在工具实现里。
- 不允许将安全控制依赖“提示词自觉”。
- 不允许把可恢复状态只保存在进程内存。

- 至少有三类 schema 可直接被配置文件使用。
- 任意能力模块都可被启用/禁用且不改代码主干。
